TACTiS2（主要模型） chronos2(老師提供benchmark) sktime(Naive模型 我自己找的benchmark)

嘗試了兩個模型作為 benchmark，但是發現兩個模型的數值都比 TACTIS2這個模型的數值還好。

chronos它是零樣本推論，所以它只要看前幾期的上下文就能預測，所以資料切塊不會影響它的效果。

naive 模型的話，它是拿昨天的數字當今天的預測，所以數據切不切塊對它來說沒有差。

但是本模型也就是 TACTIS2，它會需要先將全部的數據計算出邊緣機率，再將他們得到的邊緣機率用來計算 copula。所以將資料切塊訓練，
就相當於強迫模型在每一個小塊中重新計算邊緣模型。那這樣子下去，你和 Copula 的基礎就會產出互相衝突的局部權重，
所以表現會比其他兩個 benchmark 還要差。因為本機的記憶體不夠，所以要讓五十萬條時間序列同時丟進去訓練會無法達成，
所以只能嘗試切塊後執行。但是切塊後就會，數據就會比其他兩個 benchmark 模型還要差。

目前 TACTiS2 的做法是：
第 1～32 條序列    → 訓練 TACTiS2 A → 這 32 條的預測
第 33～64 條序列   → 訓練 TACTiS2 B → 這 32 條的預測
……
最後 16 條序列    → 訓練 TACTiS2 第 1,563 個 → 預測

把所有預測接成一張表 → 計算全部資料的誤差
這些模型使用相同架構，但各自學出不同的權重。A 不會知道 B 那組的資料，所以無法學習不同組之間的關係。

你原先想要的則是：
全部 50,000 條序列
        ↓
同一個 TACTiS2，共用一套權重並進行聯合預測
        ↓
全部序列的預測結果
Chronos 的情況又不同：目前是同一個預訓練模型分批接收資料，每批都用同一套權重，沒有另外訓練 1,563 個 Chronos；原版 Chronos 在這個入口中也沒有聯合建模不同序列。
